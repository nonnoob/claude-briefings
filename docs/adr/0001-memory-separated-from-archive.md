# 运行记忆与归档分离（MEMORY.md）

每个任务目录下用独立的 MEMORY.md 承载跨运行记忆（上次运行时刻与覆盖窗口、近期已报条目、进行中事件表），而不是让下一次运行去解析最近几份归档散文。原因：靠读最近 1–3 份归档"回忆"有三个已验证的缺陷——超过 3 天前报过的事件再出新进展会被误判为新闻而非续报；归档按保留期清理后记忆随之丢失；覆盖窗口只能从文件名猜且没有时刻精度（同日重跑无法计算增量窗口）。

## Considered Options

- 独立 MEMORY.md（选定）：机器记忆与人类可读归档职责分离，记忆寿命与归档保留期解耦，追踪事件可跨任意天数。
- 归档内嵌 frontmatter、逐份向前携带：少一个文件，但记忆链依赖上一份归档写入成功，且简报文件开头是机器数据。
- 维持现状（解析归档散文）：最简单，接受上述三缺陷。

## Consequences

- 归档保持纯人类可读，只增不改；MEMORY.md 每次运行开头读取、结尾整体重写（体积有界）。
- MEMORY.md 缺失/损坏时必须能降级：读最近 1–3 份归档重建，两者矛盾以归档为准——归档是事实源，MEMORY 只是索引。
- 写入顺序固定"先归档、后 MEMORY"，中断只会导致 MEMORY 落后（可重建），不会归档丢失。
