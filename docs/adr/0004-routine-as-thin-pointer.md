# Routine 退化为任务指针，取消 prompt 副本与运行时自愈

> 取代 ADR-0002。该 ADR 中"调度器持有运行时正文副本 + 每次运行做自愈校验"的机制自本决策起废止；其"文件为唯一权威源"的核心结论保留并强化。

调度器里注册的 prompt 不再是运行时正文的副本，而是一份约十行的**任务指针**：说明本次运行是哪个 topic-slug、去哪个状态仓库、读该任务目录下的 `SKILL.md` 正文并严格照它执行，除该文件外不接受任何其他来源的行为指令。运行的第 0 步不再做正文比对，因为不存在第二份可比的东西。状态仓库读不到或任务定义为空时，运行**直接失败退出**，不再降级为无状态运行。

决策依据：ADR-0002 已经规定"不一致时以文件为准执行本次运行"，即副本在正常路径上从不作为行为依据，它唯一的作用是仓库读不到时的兜底。为这个兜底付出的代价是持续的：每次运行做一次全文 diff、每次运行在 MEMORY 里写一行"未同步远端 prompt"、以及副本的单边漂移必须靠人工粘贴消除（2026-08-13 实测：六个任务全部漂移，其中 `daily-tech-briefing` 线上少了两个检索板块与整条 AI 排除条款，靠自愈兜了两周才被发现）。云端会话没有任务更新工具（`update_trigger` 对 http_api 创建的 routine 一律拒绝），漂移无法自动收敛，副本注定越走越偏。

放弃降级运行是刻意的：仓库读不到意味着运行记忆、已报条目清单、进行中事件表同时拿不到，此时硬出一期简报，产出的是不去重、不续报、可能大量重复上期的内容，且写不回归档。**明确失败优于看起来成功的降级**——缺失由看门狗在当天冒泡，代价是可控的"当天没有简报"。

## Consequences

- 改任务行为 = 改 `SKILL.md` 并 push，**不再需要碰 Routine**；Routine 只在改名、改频率、改模型时才需要打开。
- 术语 `运行时自愈` 废止；`运行时正文` 不再定义为"推送为调度器 prompt 的部分"。
- 装配新任务时不再需要把正文逐字粘进 Instructions，`_template` 的对应 checklist 项改为填指针模板。
- 状态仓库的可用性成为运行的硬依赖。这是有意的取舍：仓库不可达时不产出，比产出不可信内容更好。
