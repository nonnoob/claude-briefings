任务状态仓库：GitHub 仓库 `nonnoob/claude-briefings`（`https://github.com/nonnoob/claude-briefings.git`；公开仓库 clone/pull 无需认证，push 需要授权）。运行开始先就绪仓库：当前工作目录已是该仓库的检出（云端任务通常如此）则先 `git pull` 取最新；没有检出则 clone 后进入。仓库根下的 `tech-news-briefing/` 目录即本任务根目录（下称"根目录"）。**若仓库不可达（pull 与 clone 均失败）：立即停止，说明原因，不要产出简报**——没有运行记忆就没有去重、没有续报、也写不回归档，这种简报不可信；缺失会由看门狗当天告警，下次运行的覆盖窗口会自动补回这段时间。

## 第 1 步：读取运行记忆，计算覆盖窗口

- 读根目录 `MEMORY.md`，取得：上次运行时刻、已报条目清单、进行中事件表。
- 若 MEMORY.md 缺失或损坏：改读 `archive/` 下最近 1–3 份归档重建上述记忆，不报错、不阻塞；MEMORY 与归档矛盾时以归档为准。
- 覆盖窗口 = 自上次运行时刻至现在，封顶 7 天。两种边界：
  - 首次运行（无记忆亦无归档）：按过去 48 小时处理；
  - 缺口超过封顶（久未开机）：窗口内正常收录，窗口外只收至今仍重要的大事。
- 同日已运行过属正常情况（手动重跑等）：窗口就是自当天上次运行以来的几小时，只报增量；没有新内容就按第 3 步的空期骨架输出，不硬凑。
- 当前日期时间从环境获取，不要假设。

## 第 2 步：检索

用 WebSearch 分方向检索以下内容，只收录发布时间落在覆盖窗口内的新闻：

排除：深度 AI 行业新闻（模型发布、AI 公司商业与融资动态）由专门的 AI 行业简报覆盖，本简报不重复收录——谷歌生态、新品发布等板块内的产品级 AI 更新（如 Gemini 功能上线）仍照常收录。

- 去重按**事件级语义**判定：与已报条目描述的是同一事件的（换了媒体、标题、链接也算），跳过。

- 单个方向失败时降级，不中止整轮：某个检索方向被平台安全策略拦截（safeguards flagged / request blocked）、工具报错或检索配额耗尽时，跳过该方向、继续执行其余方向，按"部分成功"落盘，并在运行备注与 MEMORY.md 中注明该方向本期未覆盖。只有全部方向都无法取得任何有效内容，才算"完全失败"。

## 第 3 步：格式契约

简报的结构由下面这份骨架**逐字**规定。骨架里的 `#`、`##`、`- `、`> ` 是字面格式，不是排版强调；`<>` 里的才是要替换的内容。

```
# 📰 每日科技简报 · <YYYY-MM-DD>

> 覆盖窗口：<起> 至 <止>（常规 / 补漏：<原因>）

今日要闻：<一句话，本期最重要的一条新闻>

## <板块名>

- <一句话：谁 + 做了什么 + 关键数字或影响>。来源：<来源名称> <URL>
- 【续报】<只写增量，不重复旧细节>。来源：<来源名称> <URL>

## <板块名>

- 【传闻】<消息出自谁>：<内容>。来源：<来源名称> <URL>
```

全部板块都无实质新内容时（少见），用空期骨架，**不得编造内容凑数**：

```
# 📰 每日科技简报 · <YYYY-MM-DD>

> 覆盖窗口：<起> 至 <止>（常规）

本期没有值得报告的内容：<一句话说明各方向均已检索、窗口内无未报道过的实质新内容>。
```

板块与顺序：谷歌 / 安卓、系统更新、新品发布、科技巨头动态、芯片与硬件、科技人物动态、投融资与并购、安全与隐私、开源软件、政策与监管（按此顺序，只出现当期有内容的板块）

必须满足、且会被仓库内看门狗机械校验的几条：

- 一级标题恰好一行，以 `# ` 开头，位于全文最前。
- 覆盖窗口行紧随标题，以 `> ` 开头，**每期都有**，无论窗口是否常规。
- 板块一律用 `## `。**不得**用粗体、下划线或任何其他写法代替板块标题。
- 条目一律用 `- ` 开头的单行。条目**不得**以 `**` 开头。
- 每条必须以 `来源：<来源名称> <URL>` 结尾。URL 用裸链接，**不用** `[名称](URL)` 这种 markdown 链接语法——裸链接能让读者一眼看见域名，配合【单源】判断可信度。
- 确实拿不到公开链接的（页面已下架、仅有转引等），写成 `来源：<来源名称>（无公开链接：<原因>）`。**缺链接必须显式化**——否则"本来就没有"和"忘了挂"从产出上无法区分。
- 标记只作为条目最前缀出现，可叠加，顺序为【续报】【传闻】【单源】【矛盾】中实际适用者。
- 没有实质新内容的板块整节省略，不保留空标题。

内容要求：每节至多 2–5 条（多数板块 2–3 条），优先信号最强的内容；每条一句话讲清楚，可快速扫读，不注水。
- 涉及 CVE/漏洞的条目尽量注明编号，并给出可执行建议（如"应尽快更新"）。

## 第 4 步：落盘（成功才落盘；顺序固定：先归档、后记忆、再推送、最后回复）

- **完全失败**（检索全挂、未取得任何有效内容）：不写归档、不改 MEMORY.md，直接说明失败原因即结束——下次运行的窗口会自动覆盖这段时间。
- **部分成功**（个别方向检索失败）：照常落盘，在 MEMORY.md 与运行备注中注明哪些方向本期未覆盖。
- 先写归档：`archive/tech-news-briefing_<YYYY-MM-DD>.md`（运行当天实际日期）；当天已存在同名文件时改用 `tech-news-briefing_<YYYY-MM-DD>_<HHmm>.md`——**永不覆盖已有归档**。归档内容 = 第 3 步骨架产出的简报正文，到最后一个条目为止；**运行备注不写进归档**（它描述运行状态，不是内容）。
- 落盘前自检一遍：对照第 3 步那几条硬规则逐条核对本期产出，不合格就改完再写文件。
- 后整体重写 `MEMORY.md`，固定三节：
  1. 本次运行时刻与实际覆盖窗口；
  2. 已报条目清单：保留最近 14 天，一行一条，格式"日期 | 一句话事件描述（谁+干了什么）| 代表性链接"，描述只写事件本身、不携带"(同日二次运行)"之类的运行批注；
  3. 进行中事件表：预期还有后续、需要跨运行追踪的事件，每条含"事件、最后进展日期、下一步关注点"，关注点写成具体可验证的预期（如"等 X 官宣""等 Y 回应"），供下次定向检索；事件已闭合或连续 14 天无新进展则移出（可在当期简报注一句）；至多保留 10 条，按重要性取舍——因条数上限而踢出仍在推进的事件时，在运行备注注明踢出了哪条、为什么。
- 再提交推送：`git add` 本任务根目录并 commit（消息格式 `tech-news-briefing: <YYYY-MM-DD>`）。**推送目标固定为分支，不要尝试直推 main**：`git push origin HEAD:refs/heads/claude/tech-news-briefing-<YYYY-MM-DD>`；若该分支已存在导致推送被拒，改用 `claude/tech-news-briefing-<YYYY-MM-DD>-<HHmm>` 重推一次。仓库内的 auto-merge 工作流会把它并入 main 并删除分支。**推送走哪个分支名不是异常，不要写进运行备注。**仅当推送彻底失败（两次都被拒）时才在运行备注告警。
- 归档永久保留：不删除、不清理 `archive/` 下任何文件（非交互运行中删除文件会触发权限请求而中断任务；清理只由用户手动进行）。

默认仅允许：写本任务根目录内的文件；对仓库 `nonnoob/claude-briefings` 的 git add/commit/push（仅含本任务根目录内的变更）。其余一切外部写操作（发消息、发邮件、发布内容、删改任务目录外的数据）一律禁止。无额外授权。

## 运行结束：产品

本次运行面向用户的交付物，是**会话的最后一条消息**。它的正文必须是刚写入归档文件的那份简报，**逐字相同，不得增删、不得改写**。

- **不得**用"已完成""详见仓库""见 archive"之类的指针或摘要代替简报正文。
- 最后一条消息里只允许两样东西：简报正文；以及仅在本次运行确有异常或特殊动作时（MEMORY.md 缺失重建、部分方向未覆盖、补漏封顶截断、事件表因上限踢出、推送彻底失败），末尾追加的一行普通文字 `运行备注：<一句话>`。不用尖括号标签，不重复简报内容。
- 检索、核实、落盘各阶段**不要输出面向用户的解说文字**（"我先检索一下……""正在写入归档……"）。需要留痕的判断写进 MEMORY.md，不写进对话。
