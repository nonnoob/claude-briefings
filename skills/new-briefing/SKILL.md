# new-briefing — 从 topic 到定时简报任务

> **安装**：把本目录复制到 `~/.claude/skills/new-briefing/`，并替换下文占位符：`<仓库检出路径>`（你本机的仓库 clone 位置）、`<你的仓库>`（如 `you/your-briefings`）；默认受众、语言、时区也可顺手改成自己的。

用户只抛一个 topic，其余全部由你决定，不追问、不让用户操心设计细节。

**装配规范的唯一权威是 `<仓库检出路径>/_template/SKILL.md` 的装配说明。本技能不复述其 checklist（复述必漂移）——先读模板，照它执行；本技能只补充下面几件模板管不到的事。**

## 输入解析

- **topic**：用户消息里的主题，可以是中文。
- **频率/时间**（可选）：用户顺口带了就用；没带默认**每天 09:00（用户本地时区）**。频率只进 Routine 的调度配置，永不写入任务正文（模板铁律）。
- **替换旧任务**（可选）：用户提到"替换原来的 XX"时，装配后提醒用户删除旧 Routine。

## slug 与冲突检查

- slug 由你定：英文小写连字符，语义清晰（如 `semiconductor-daily-briefing`）。
- 若 `<仓库检出路径>/<slug>/` 已存在：这是已有任务。问用户一次：是想改它（直接编辑该 SKILL.md 并 push，下次运行自愈生效，不需要走本技能），还是另起新 slug。

## 板块与信息源设计（你的核心增值）

自主完成，标准如下：

1. 先想清楚这个 topic 的读者真正想跟踪什么：产业动向？产品发布？技术突破？监管政策？资金流向？拆成 3–6 个固定板块。
2. 对不熟悉的 topic，可先 WebSearch 摸底该领域的优质信息源（一手官方渠道 + 高信号媒体 + 有 track record 的爆料人/行业内部人士），把具体源名写进检索方向。
3. 明确排除项：与 topic 无关的邻近噪音（写 1–3 条），以及与已有其他简报任务重叠的部分（重叠内容归属一个任务，另一任务显式排除）。
4. 传闻默认收录（模板已内置【传闻】机制）；仅当 topic 性质明显不适合传闻（如医药安全类）才写排除，并向用户说明。
5. 语言与受众按仓库既有任务的默认值。

## 装配与收尾

1. 按模板装配说明执行：建目录、实例化、逐项自检，然后 **git commit + push**——云端 Routine 读的是远端 main，未 push 的装配不生效。
2. 把新任务目录名加进 `.github/workflows/auto-merge-briefings.yml` 的目录白名单，随同提交。
3. Routine 需要用户在网页上创建（CLI 无法代建），给出如下指引：
   - 打开 claude.ai/code/routines → New routine；
   - Name = `<slug>`（纯 slug）；
   - Instructions = 该 SKILL.md 的**运行时正文，逐字**。边界：跳过 frontmatter（两条 `---`）及紧跟的空行，自第一个非空行起到文件末尾；
   - Select repositories 绑定 `<你的仓库>`；触发器选 Schedule，默认 Daily 09:00（本地时区，DST 自动处理）；
   - **创建后**进编辑弹窗按最小权限移除不需要的连接器（创建表单里的移除不会生效），并确认模型选择。
4. 交付时告知用户：首次运行 archive/ 为空、MEMORY.md 缺失是正常初始态，会自举；以后改简报内容直接改 SKILL.md 并 push（自愈机制下次运行生效）；改运行时间只在 Routine 调度里改，永不写入正文。
